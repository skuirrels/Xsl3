# Xsl3 1.3.3

This release adds experimental streaming opt-in per stylesheet through
`XsltSettings.StreamedExecution` in [PR #44](https://github.com/skuirrels/Xsl3/pull/44).

## Execution settings

Pass the settings to `XsltCompiler.Settings` or to `XslCompiledTransform.Load` when loading
stylesheet source.

- `true` opts eligible stylesheets into forward execution.
- `false` selects tree execution for that stylesheet.
- `null` is the default. Execution uses trees unless the process sets `XSL3_STREAM_STRICT=1`.

`Streamability` still controls static analysis. Caller-owned readers remain borrowed. Saved
stylesheets retain the execution mode and capacity chosen at compile time, and the default
fork buffer is 64 logical input events. The [getting-started guide](../getting-started.md#experimental-streaming)
shows how to opt in.

## Verification and limits

On the reviewed runtime commit `235e8af`, all four [CI jobs](https://github.com/skuirrels/Xsl3/actions/runs/43276850188)
passed. The [original Phase 7 run](https://github.com/skuirrels/Xsl3/actions/runs/43276833760) passed
all 32 memory budgets, with all 96 memory and 126 benchmark outputs matching 1.3.2. Four of seven
throughput targets passed. The remaining stream/tree ratios were 1.100× for identity, 1.453× for
fork, and 1.090× for source-document against the original 1.0× limit.

Streaming remains experimental with `supports-streaming = no`. Supported streaming still requires
the original Phase 7 gates. Update `Xsl3`, `Xsl3.Build` and `Xsl3.Cli` together to **1.3.3** and
regenerate saved stylesheets with matching packages.
