# Xsl3 1.3.2

This experimental streaming checkpoint ships the integrated runtime and verification work from
[PR #40](https://github.com/skuirrels/Xsl3/pull/40) with the 1.3.1 execution defaults.

## Changes

- Skip compiler-excluded descendant events when a fork is their sole consumer. Preserve source
  positions, reader demand, validation, cancellation and the full event path for replay and observers.
- Construct named per-source merge groups on demand, preserving member values, ordering and identity.
- Reduce streamed reader-stack lookups and extend coverage for error/retry behavior, read positions,
  saved stylesheet execution and fork continuation.
- Use a deterministic missing-document resolver in the stock differential test.

## Execution and compatibility

Execution defaults to trees. Set `XSL3_STREAM_STRICT=1` before compiling or loading stylesheet
source to try forward execution for eligible stylesheets. `Streamability = Strict` controls
static checking. `XsltSettings.StreamingBufferCapacity` defaults to 64 logical input events.
Explicit capacities and the execution mode and capacity in saved stylesheets are preserved.
Streaming remains experimental and `supports-streaming` remains `no`.

The original Phase 7 memory and throughput gates continue to define acceptance for supported
streaming. The pre-checkpoint integration head, including the proposed changes to default
execution selection and buffer capacity, is preserved on
[`feature/p7-full-qualification`](https://github.com/skuirrels/Xsl3/tree/feature/p7-full-qualification).

Update `Xsl3`, `Xsl3.Build` and `Xsl3.Cli` together to **1.3.2** and regenerate saved stylesheets
with matching compiler/runtime packages.
