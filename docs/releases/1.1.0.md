# 1.1.0: streaming foundations

Version 1.1.0 closes **P7A**, the implemented streaming foundations and related correctness work.
Streaming remains experimental and unsupported; `supports-streaming` continues to return `no`.
Normal execution remains tree-based. Full P7 is deferred.

## Changes

- Add streamability analysis and Strict/Fallback settings, plus reader-based entry points and legacy secondary-result
  delivery through `XsltArgumentList.ResultDocumentHandler`.
- Add experimental forward execution for the implemented initial-mode/source-document, iterate, grouping,
  accumulator, merge, fork and explicit-grounding cases.
- Correct focus, parameter, shared-resource and result lifetimes, source validation, and annotation/whitespace handling.
- Improve saved stylesheet portability between .NET 8 and .NET 10, including persisted schemas and typed static
  nodes. Retained saved formats remain covered by compatibility consumers; unsupported metadata fails explicitly.
- Preserve built-in types in saved schema-qualified attribute patterns.
- Resolve temporal state only when required and improve integer lexical parsing while preserving arbitrary precision.

## Upgrading

Update `Xsl3`, `Xsl3.Build` and `Xsl3.Cli` together to **1.1.0**. Regenerate saved stylesheets with the matching compiler/runtime
packages. Runtime compilation still requires dynamic code; NativeAOT consumers use saved stylesheets.

```sh
dotnet add package Xsl3 --version 1.1.0
dotnet add package Xsl3.Build --version 1.1.0
dotnet tool update --global Xsl3.Cli --version 1.1.0
```

Streamability declarations are now checked with `XsltStreamabilityMode.Strict` by default. A stylesheet declared
streamable but rejected by the implemented analysis can raise `XTSE3430` during compilation. Consumers that want
ordinary tree execution for such declarations can explicitly select fallback:

```csharp
var settings = new XsltSettings
{
    Streamability = XsltStreamabilityMode.Fallback
};
```

This setting controls analysis. Normal execution remains tree-based. Experimental forward execution is a
development capability, without a supported streaming or memory-budget guarantee. Xsl3 owns and disposes the
writers returned by secondary-result handlers. A handler can receive partial output before a later transformation
error; see [migration guidance](../migration.md).

## Validation and limits

The frozen implementation passes Release/Debug unit tests on .NET 8/10, applicable upstream and byte-for-byte
differential tests, current W3C baselines, saved-assembly consumers and NativeAOT checks. The ordinary performance
gate passes. [P7A close-out](../plan/p7a-closeout.md) records exact counts, evidence and remaining publication checks.

The 1.1.0 packages are: `Xsl3`, its symbol package, `Xsl3.Cli`, and `Xsl3.Build`.
Clean consumers restore the Xsl3 packages solely from the local candidate feed into an isolated cache; cached
Microsoft SDK/toolchain packages are provided separately. Managed consumers pass on .NET 8 and .NET 10 with two
independent input datasets, exercising package-generated saved stylesheets, reader APIs, Strict/Fallback analysis,
secondary-result delivery/disposal and byte comparison with stock XSLT 1.0. Both packaged CLI frameworks pass,
as does a fresh local tool installation. A .NET 10 macOS ARM64 NativeAOT consumer publishes with warnings as errors
and passes both datasets using saved stylesheets and secondary results, with globalization enabled.

The local validation bundle at `artifacts/releases/1.1.0/` retains package/source hashes, frozen source, consumer
fixtures, logs and conformance/performance evidence. Hosted CI and the tag-driven release workflow provide
release-commit and package-publication evidence.

Full P7 is deferred: analysis-suite reconciliation, the 20 MiB absolute memory target, several streaming throughput
targets, general retained-model bounds and hosted platform acceptance remain unfinished. Their unchanged checks
continue in the separate experimental workflow. No full streaming conformance or universal performance claim is made.
