# Xsl3 1.3.1

Release date: 6 November 2026. This bounded release strengthens experimental streaming verification
and separates native initialization diagnostics from the original P7 acceptance workflow.

## Changes

- Direct tests cover forward execution through both public APIs, group read/drain positions,
  retained navigator memory, fork grouping/sorting payload retention and declaration-order output.
- Debug compilation records whether the streamed optimizer verifier actually ran and completed.
  Strict streaming CI checks that evidence and exercises a missing-verifier negative control.
- A hidden-grounding negative control shows that a forward source and correct output alone cannot
  prove bounded memory; the retained-memory check rejects the deliberately grounded control.
- Experimental probe URIs use HTTP to avoid incidental ICU initialization. Original input sizes,
  whole-process memory budgets and throughput targets remain unchanged.
- Native initialization tracing has a separate workflow and Linux PR check. The daily/manual
  P7 memory and throughput acceptance workflow is preserved unchanged.

## Verification and limits

The release workflow builds, tests and packs the tagged source before the owner's required NuGet
publication review. Ordinary CI covers the unit, upstream, differential, W3C, NativeAOT and
micro-performance checks. The diagnostic is evidence collection, not an acceptance result.

Full streaming remains experimental and unsupported. Default execution stays tree-based,
forward execution requires the existing development opt-in, and `supports-streaming` remains `no`.
The separate integrated runtime qualification branch is not included in this release. This release
does not claim that all original P7 memory and throughput gates pass or that P7 is complete.

Update `Xsl3`, `Xsl3.Build` and `Xsl3.Cli` together to **1.3.1** and regenerate saved stylesheets
using matching compiler/runtime packages.
