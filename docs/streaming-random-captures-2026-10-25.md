# Deferred random-generator state, 2026-10-25

This extends the [library function checkpoint](streaming-library-captures-2026-10-25.md) on
`feature/p7-streaming-analysis`. Random-generator maps now spill their `next` and `permute` callables
as actual numeric state. Full Phase 7 remains active and `supports-streaming` remains `no`.

## Representation and compatibility

The engine's random-generator factory associates immutable generator state and the callable's role
with its native implementation. Only that factory can set the descriptor. Arbitrary native/provider
callbacks retain their actual identity; the codec does not inspect delegates or infer captured state.
The scratch record contains the actual unsigned 64-bit state and role for each value, without a
retained per-state metadata table. Graph references preserve aliases through maps and coercion wrappers.

Replay uses the same factory as ordinary random-generator creation. Seed hashing, SplitMix64,
Fisher–Yates permutation and the next-state transition are unchanged. Existing public function
signatures, names/descriptions, generated helper entry points and saved-constant layout are unchanged.
Permutation keeps the supplied items' identity and leaves the argument sequence intact. Callable
numeric state remains immutable and can be invoked repeatedly by separate fork workers.

The preceding accepted core reproduces two new retention/representation failures on each framework:
original callables remain in the identity table. The new collection test writes 1,000 distinct seeded
generator maps, replays them in reverse order, compares subsequent generations and proves the
original maps and 2,000 callable closures can be collected while the store remains alive. Tests also
cover edge integer seeds, 32 next generations, callable metadata, repeated permutation, shared
coercion targets, node position identity and generic callback identity. The initial test's reference
comparison of cloned navigators was corrected to compare their actual node positions; no engine
identity behavior was changed to satisfy that assertion.

## Actual seeded-generator memory matrix

Each source row creates `random-number-generator(string(@id))` in a streamable `map(*)` accumulator.
This records both native callables with a distinct actual state per source ID. A deferred climbing
`except` selects odd rows; output invokes the recorded permutation on the 20-digit ID, a colon and
the numeric ID, then joins the resulting items. Each row's random state therefore affects its text.
The canonical generated XML input is unchanged.

The independent verifier calculates the existing FNV seed hash over the declared type name and each
source ID, then applies the existing SplitMix64/Fisher–Yates algorithm to the output tokens. It hashes
the resulting stream rather than embedding a desired digest. Algorithm constants come from the
existing implementation, and the seed's type name comes from its actual declared engine type.
The verifier first passed against the preserved preceding core at exact **10 MiB**, then matched the
NativeAOT candidate's complete output. Those checks are preserved under
`/tmp/xsl3-p7-random-captures-before-scale/` and `/tmp/xsl3-p7-random-captures-candidate/scale/`.
